Four-Member Responsibility & Module Contract Plan

          

            Implemented across both the standalone Web App and the full-stack Python + JS codebase (realtime_packet_router_simulator_fullstack.zip).
          

          

            

              
Member 1 — Frontend & UI Validation

              
frontend/index.html

              
Builds route & packet simulator screen; selects start/destination/stops; validates empty & duplicate inputs; renders animated packet streams and leg breakdowns.

            

            

              
Member 2 — City/Network Data & Graph

              
backend/graph_module.py | js/graphModule.js

              
Creates 8–12 nodes (A–G core + H–J extended); builds Adjacency List and O(1) Hash Map; validates non-negative edge weights and disconnected node G.

            

            

              
Member 3 — Shortest-Path Engine

              
backend/dijkstra_engine.py | js/dijkstraEngine.js

              
Implements Dijkstra with a custom binary Min-Heap priority queue; tracks distances & predecessors; reconstructs paths; benchmarks against O(V²) linear scan.

            

            

              
Member 4 — Multi-Stop Planner & Integration

              
backend/multistop_planner.py | js/plannerModule.js

              
Caches pairwise Dijkstra results; runs Nearest-Neighbour & Exact k! search; assembles legs while deduplicating junction nodes (such as B in A→C→B→D→F).

            

          


          
          

            
Viva & Presentation Readiness Guide (Page 10 Questions)

            

              

                1. Why are graphs and adjacency lists suitable for representing roads & router networks?
                
Real-world road and packet networks are sparse graphs where each node connects to only a few neighbours. An Adjacency List uses O(V + E) memory and iterates only over actual outgoing links, whereas an Adjacency Matrix wastes O(V²) space on non-existent links.

              

              

                2. How does a binary Min-Heap help Dijkstra's algorithm?
                
Dijkstra repeatedly extracts the unvisited node with the smallest tentative distance. A binary Min-Heap performs extraction and priority updates in O(log V) time instead of O(V) linear scanning, improving total time complexity from O(V²) to O((V + E) log V).

              

              

                3. What does the Nearest-Neighbour heuristic guarantee, and what does it not guarantee?
                
Nearest-Neighbour runs in polynomial time O(k²) using cached shortest paths and always picks the closest unvisited stop next. However, because it is greedy, it does not guarantee the globally shortest multi-stop tour across all k! permutations—which is why our planner compares Nearest-Neighbour against Exact k! search.
